## 二、详细版（3～5 条，适合简历正文）

1. **独立完成后端架构与核心链路**：基于 Spring Boot 3 + MyBatis 手写 SQL 实现作品、章节、正文、评论、书架、
   历史、关注等 30+ REST 接口，统一 `{code,data,message}` 响应与错误码体系；采用 Interceptor + ThreadLocal
   做无状态 JWT 鉴权，请求结束强制清理上下文，读者与管理员使用两套独立密钥。
2. **设计「私人 TXT 导入 → 投稿 → 审核发布」业务闭环**：自研 TXT 解析器（UTF-8 BOM / UTF-8 / GB18030
   依次探测，识别“第 N 章”标题拆章，拒绝二进制与超限文件），私人原件与公开副本分表存储；审核通过时在单个
   事务内批量复制章节与正文，失败整体回滚，删除原件不影响已发布作品。
3. **热点读缓存与降级**：封装 `JsonRedisCache`，为章节正文、首页、分类、榜单增加短 TTL 缓存与 JSON 序列化，
   Redis 异常自动回退数据库，公开接口每次校验作品上架状态，避免缓存绕过下架。
4. **安全与越权防护**：私人作品的全部读写都在 SQL / 服务层校验 `user_id` 归属，他人作品与不存在作品返回同一
   错误码，防止 ID 探测；封面存私有 OSS 桶，审核通过后才复制为公开读对象。
5. **多端交付与上线**：Vue 3 读者站、Vue 3 + Element Plus 管理端、uni-app 移动端共用一套接口；在 Ubuntu
   上用 Nginx + systemd + Certbot 部署，MySQL/Redis 仅监听本地、最小权限数据库账号、环境变量注入密钥，
   配置每日定时备份并推送独立 OSS 桶。

## 四、面试可展开的技术点（每个都要能画图讲清）

| 面试官可能问 | 你的答法要点 |
| --- | --- |
| 为什么用拦截器而不是 Spring Security 过滤器链？ | 现状是 Security 只用于 BCrypt，鉴权在 MVC 拦截器；可讲清取舍，并说明后续会合并成 Filter + `SecurityContext` |
| 缓存一致性怎么保证？ | 目前是写后删 key + 短 TTL 兜底；主动指出击穿风险，给出互斥锁 / 逻辑过期的改法 |
| 上传 20 MB TXT 怎么防止打爆内存？ | multipart 限制 23 MB、流式读取、解析后不落原始文件、最多 5000 章 |
| 大章节正文怎么存？ | `book_content` 与目录分表，LONGTEXT 独立表避免目录查询带出大字段 |
| 分页深翻页怎么办？ | 目录按 `chapter_num` 游标，offset 上限保护；可讲 keyset 分页改造 |
| 部署安全做过什么？ | 端口收敛、最小权限账号、密钥环境变量、管理端 Basic Auth + JWT 双层、备份到独立桶 |

## 六、表述红线

- 不要把上游开源项目写成「从零手写」：读者站 UI 基于 novel-front-web 二次开发，面试官很可能认识这个项目。
  统一表述为「基于开源阅读端二次开发，后端 / 管理端 / 移动端 / 部署为自研」，可信度反而更高。
- 不要写「百万级并发」「高可用集群」这类没做过的词；写「单机部署，压测 QPS xx」更稳。
- 「精通」一律换成「熟悉 / 实践过」。
