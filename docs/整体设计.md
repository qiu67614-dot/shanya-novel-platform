# 小说平台 · 全栈项目整体设计

> 目标:基于现有前端 `novel-front-web`(Vue 3),补齐缺失功能,并**从零开发一套 Java Spring Boot 3 后端**,形成一个完整的、可上线的小说平台。
>
> 状态:设计稿 v1 · 待评审迭代

---

## 1. 项目目标与范围

### 1.1 目标
打造一个前后端分离的小说平台,包含 **小说门户 + 会员中心 + 作家后台 + 平台管理后台** 四大部分。

### 1.2 现状与差距

| 模块 | 现状 | 本次目标 |
|---|---|---|
| 小说门户(首页/检索/排行/阅读) | ✅ 已有 | 保持并修复 |
| 小说评论 | ⚠️ 半成品(无回复/点赞/分页) | 补齐 |
| 书架/阅读历史 | ❌ 缺失(代码有注释残留) | 新增 |
| 会员中心 | ⚠️ 仅资料 + 我的评论 | 补书架/历史/充值 |
| 作家后台 | ⚠️ 简陋(发书/章节/AI) | 增强(统计/审核) |
| 充值/订阅/VIP 章节 | ❌ 完全缺失 | 新增(核心增量) |
| 新闻 CMS | ❌ 只有前台读 | 新增后台发布 |
| 平台管理后台 | ❌ 完全缺失 | 新增(独立 admin 前端) |

## 2. 总体架构

```
┌─────────────────────────────────────────────────────┐
│                     浏览器 (Vue 3)                    │
│  小说门户(现有)  +  会员中心  +  作家后台  +  admin     │
└──────────────────────┬──────────────────────────────┘
                       │  HTTP / JSON  (REST)
                       ▼
┌─────────────────────────────────────────────────────┐
│                Spring Boot 3 后端 (novel)             │
│  /front/* 门户  /author/* 作家  /admin/* 管理          │
│  Controller → Service → Mapper(MyBatis-Plus)         │
└───────┬──────────────────┬──────────────────┬────────┘
        │                  │                  │
        ▼                  ▼                  ▼
     MySQL 8           Redis 7          Elasticsearch(可选)
   (业务数据)        (验证码/缓存/会话)    (全文搜索,进阶)
```

**前后端交互约定**(已由前端代码锁定,后端必须遵守):
- 响应体统一为 `{ code, data, message }`;成功 `code = "00000"`;失败 `code` 为具体错误码 + `message`。
- 登录过期 `code = "A0230"`(前端收到后自动清 token 跳登录页)。
- 认证方式:请求头 `Authorization` 直接携带 JWT token(无 `Bearer` 前缀)。
- 图片地址:后端返回相对路径,前端用 `VUE_APP_BASE_IMG_URL` 拼接。

```
    │   ├── core/
    │   │   ├── config/                    # Web/MyBatisPlus/Redis/CORS 配置

    │   │   ├── category/                  # 分类
    │   │   ├── news/                      # 新闻
    │   │   ├── user/                      # 注册登录、资料、书架、评论、反馈
    │   │   ├── author/                    # 作家(注册、作品、章节、AI)
    │   │   ├── pay/                       # 充值、订单、订阅
    │   │   └── admin/                     # 平台管理(作品审核、新闻发布、用户管理)

    │   └── resources/

```

**分层规范**:`Controller`(参数校验/组装响应) → `Service`(业务逻辑/事务) → `Mapper`(数据访问)。业务异常统一抛 `BusinessException(code, msg)`,由全局异常处理器转成 `RestResp`。

## 5. 数据库设计

> 命名:小写下划线;主键 `bigint` 自增(或雪花 ID);所有表带 `create_time` / `update_time`。
> 索引原则:外键字段、常用查询字段建索引。

### 5.1 用户与权限
- **sys_user** 用户表:`id, username(手机号,唯一), password(BCrypt), nick_name, user_photo, user_sex, user_birthday, user_phone, user_email, status(0正常/1禁用), create_time, update_time`
- **author_info** 作家表:`id, user_id(唯一), pen_name, tel_phone, chat_account, email, work_direction(0男/1女), status(0申请中/1通过), create_time, update_time`
- 角色:普通用户/作家/管理员 三者。简化方案:角色由"是否存在于 author_info" + "sys_user 角色字段"判断;进阶可用 RBAC(`sys_role`/`sys_user_role`)。

### 5.2 作品
- **book_category** 分类:`id, work_direction, name, sort, create_time, update_time`
- **book_info** 作品:`id, work_direction, category_id, category_name(冗余), pic_url, book_name, author_id, author_name(冗余), book_desc, score, book_status(0连载/1完结), visit_count, word_count, comment_count, last_chapter_id, last_chapter_name(冗余), is_vip(整本是否收费), create_time, update_time`
- **book_chapter** 章节:`id, book_id, chapter_num, chapter_name, chapter_word_count, is_vip(是否付费章), chapter_price(分), chapter_update_time, is_publish(是否发布), create_time, update_time`
- **book_content** 章节正文:`id, chapter_id(唯一), content(LONGTEXT)` — 学习型先单表,进阶用 ShardingSphere 分表或对象存储
- **home_book** 首页推荐位:`id, type(0轮播/1顶栏/2本周强推/3热门/4精品), book_id, sort, create_time`
- **home_friend_link** 友情链接:`id, link_name, link_url, sort, create_time`

### 5.3 阅读/收藏/评论
- **user_bookshelf** 书架:`id, user_id, book_id, pre_chapter_id(上次读到), create_time` + `(user_id, book_id)` 唯一索引
- **user_read_history** 阅读历史:`id, user_id, book_id, chapter_id, create_time`
- **book_comment** 评论:`id, book_id, comment_user_id, comment_user_name, comment_content, reply_count, create_time`
- **book_comment_reply** 评论回复:`id, comment_id, reply_user_id, reply_user_name, reply_content, create_time`

### 5.4 付费/订阅(新增模块)
- **pay_order** 充值/支付订单:`id, out_trade_no(商户订单号), trade_no(第三方流水号), user_id, pay_channel(1支付宝/2微信), pay_amount(分), pay_type(1充值/2订阅), pay_status(0待支付/1成功/2失败), create_time, update_time`
- **user_subscription** 订阅记录(买了哪些章):`id, user_id, book_id, chapter_id, pay_amount, create_time` + `(user_id, chapter_id)` 唯一索引
- 余额:可在 `sys_user` 加 `balance(分)` 字段,或独立 `user_balance` 表(推荐独立,便于流水审计)。

### 5.5 其它
- **news_info** 新闻:`id, category_id, category_name, title, source, content, create_time, update_time`
- **news_category** 新闻分类
- **user_feedback** 反馈:`id, user_id, content, create_time`
- **sys_log** 操作日志(可选):`id, user_id, module, operation, ip, create_time`

## 7. 认证与权限

1. **JWT**:登录成功后签发 token(claims 含 `uid`),前端存 localStorage 并在请求头 `Authorization` 携带。
2. **校验链**:`AuthInterceptor` 拦截 `/author/**`、`/front/user/**`(除 login/register)、`/pay/**`、`/admin/**`;解析 token → 校验过期 → 写入 `UserContext`(ThreadLocal)。
3. **过期处理**:token 过期/非法,抛出异常 → 全局异常处理器返回 `code = "A0230"`(前端据此跳登录)。
4. **角色控制**:`/author/**` 需是作家(查 author_info 且 status=1);`/admin/**` 需管理员角色。
5. **密码**:BCrypt 加密存储。
6. **验证码**:`/front/resource/img_verify_code` 生成图形验证码,`sessionId → code` 存 Redis(带过期),注册时校验。

## 8. 核心业务流程

### 8.1 阅读流程
```
图书详情 → 点击阅读 → 章节列表/正文
正文请求 /front/book/content/{chapterId}:
  ├─ 免费章 → 直接返回正文
  └─ 付费章(is_vip=1) → 校验 user_subscription 是否已购
       ├─ 已购 → 返回正文
       └─ 未购 → 返回 code(如 "B0001" 未订阅) → 前端引导充值/购买
```

### 8.2 充值订阅流程
```
充值:创建订单 → 调用支付渠道(开发环境用沙箱) → 支付回调验签 → 更新余额+订单状态
订阅:前端调用 /pay/subscribe {bookId, chapterId?} → 后端校验余额 → 扣款 → 写入 user_subscription → 返回成功
```

### 8.3 评论流程
发评论(登录校验)→ 后端存储 → 返回。新增:回复(book_comment_reply)、点赞、分页。
